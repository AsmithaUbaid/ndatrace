# UI-to-report content map

This map treats the project UI as an analytical index, not a source of record. Every retained claim was checked against the source hierarchy: professor requirements and proposal for intended objectives; canonical experiment artifacts for results; notebooks and decision records for context; UI code and generated presentation data for overlooked framing. No frontend file was changed.

## Documented UI discrepancies

- `scripts/build_project_presentation_data.py` describes the original risk-sensitive target as RAG versus Rule and says it was met. The submitted Problem Statement defines the target as RAG versus FULL. Canonical TEST gives 69.1%→70.3%, a +1.2-point change against a required +5.0; the report records **not achieved**.
- The UI flow label says “256 tok, overlap 50.” `pipeline/frozen_rag.py` and `docs/architecture.md` show that `CHUNK_OVERLAP=50` is a recorded but inert setting; `clause_aware_chunk()` receives no overlap. The report therefore states **clause-256, no effective overlap**.
- The UI cost-to-serve model can be read as avoiding human review when Joint succeeds. The implemented product keeps human final authority unconditional. The report uses mandatory verification for all cases and treats further investigation as a declared sensitivity assumption.

## Deliberate omissions

Interactive filters, animation, detailed case text, code-module cards, demo controls and exhaustive OWASP category cards were omitted because they do not add an independent academic finding. Their strongest verified implications are represented in prose, tables or the four print-oriented figures.
