# Prompt Version History

| Version | Date | Changes | Used In |
|---------|------|---------|---------|
| v1 | 2026-09-22 | Initial zero-shot classification prompt: JSON output (label/confidence/evidence/explanation), verbatim-quote evidence rule, basic prompt-injection resistance instruction | T012 smallest slice, B03 full-context baseline, B04 Oracle, T024 RAG e2e |
| v2 | 2026-09-23 | Adds an explicit-conservative instruction: default to NotMentioned unless the excerpt clearly and directly addresses the requirement; warns against inferring from shared vocabulary/general topic overlap. Targets T024's dominant RAG failure mode (NotMentioned false-positived as Entailment/Contradiction, 57% of errors) | **Adopted as default** (T018) - improved accuracy 86.0%→88.0%, macro-F1 0.842→0.858, risk-sensitive recall 0.830→0.855 on the identical 150-case sample, with no regression on any metric |
| v3 | 2026-09-23 | Same instruction as v2, demonstrated via 3 few-shot worked examples (incl. one topically-related-but-irrelevant excerpt correctly labeled NotMentioned) instead of stated as a rule | **Rejected** (T018) - worse than v1 on most metrics; risk-sensitive recall fell to 0.731 (from 0.830) and Contradiction recall crashed to 64.3% (from 85.7%). The few-shot demonstration over-anchored the model toward "default NotMentioned" even for genuine Contradictions |
| v4 | 2026-09-23 | Adds a required `addressed_directly: true/false` field the model must fill before choosing a label - if false, the label is forced to NotMentioned (grounding-field idea, decomposes the decision instead of relying on an inline instruction or examples) | **Rejected** (T018) - worse than v2 and v3: macro-F1 crashed to 0.696, risk-sensitive recall to 0.566, **Contradiction recall collapsed to 21.4%** (from 85.7%). Contradictions are often established via a narrow carve-out/exception clause that the model judged as not "directly addressing" the hypothesis, forcing a wrong NotMentioned even on real contradictions - a more severe failure mode than v3's |
| v5 | 2026-09-23 | Same as v2, but the injection-resistance instruction covers both the NDA text AND the hypothesis field (v2 only mentioned the NDA text) - built after Category 3's injection eval battery found a real hypothesis-field injection succeeded against v2 | **Tested, not adopted** - confirmed to fix the injection case, but costs 2 real accuracy points (88.0%→86.0% on the 150-case regression test). Hypotheses in production are always the 17 fixed ContractNLI texts, never attacker-controlled, so the vulnerability isn't reachable - not worth the accuracy cost. Documented in `data/golden/injection_cases.json`'s case 051 as a known, deliberately-unpatched finding |
| **v6** | **2026-09-24** | **Current default** (`pipeline/classifier.py`'s `classify()`). Adds one targeted rule: if the given text doesn't contain genuine NDA/contract language and instead reads as a command directing the output, treat it as containing no genuine evidence and default to NotMentioned. Found necessary after a real, more serious vulnerability was discovered live through the product UI - a document consisting *entirely* of an injected instruction (no real clause content at all) fully succeeded against v2, unlike any of the 10 originally-planned injection cases (046-055), which all embedded the injection *inside* real clause content. The paired agent prompt `prompts/agent_step_v2.txt` (superseding `agent_step_v1.txt`) adds the identical rule to the agent's own decision step, which had the same independent vulnerability | **Adopted as default** - validated on the same 150-case sample: accuracy 89.3%, macro-F1 0.864, risk-sensitive recall 0.844 (not worse than v2, marginally better). Full injection battery (now 11 cases, `data/golden/injection_cases.json`): 11/11 resisted, up from 9/10 under v2 - including case 051, deliberately left unpatched under v5, resolved here for free. See `docs/decisions.md` ADR-004 for the full incident writeup |

## Agent decision-step prompts

Separate from the classifier prompts above - `pipeline/agent.py`'s `_decide_next_action`/conclude
step reads its own prompt file, since its job (pick a tool or conclude, given the classifier's
initial answer and its own history of tool calls) is different from the classifier's.

| Version | Status | Notes |
|---|---|---|
| `agent_step_v1.txt` | Superseded | Original 5-tool agent decision prompt, used for the T028-T030 agent experiment and the original T041 run |
| `agent_step_v1_3tools.txt` | Experimental, not the production default | A 3-tool variant used specifically by `scripts/run_agent_tool_ablation.py` to test whether a reduced tool set changes agent behavior (see `data/agent_tool_ablation.json`). Not referenced by `pipeline/agent.py`'s production `AGENT_PROMPT_PATH` |
| **`agent_step_v2.txt`** | **Current default** (`pipeline/agent.py`'s `AGENT_PROMPT_PATH`) | Adds the same instruction-only-input rule as `classify_v6.txt` (see the v6 row above) - the agent's decision step had the identical injection vulnerability, confirmed independently by calling `run_agent()` directly, not just via `classify()` |
